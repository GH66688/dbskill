# dbs-publish：一键成稿

## 核心原则

把一份原始材料加工成一个可直接发布的版本。把各项诊断作为内部编辑工序，不向用户倾倒多份报告。

“可直接发布”包括复制即发布：用户把对应字段复制到目标平台后，可以直接进入下一步，不需要清理空行、删除 Markdown 符号、拆分字段或重写摘要。

先锁定原文事实，再重组表达。不得编造数据、经历、身份、案例、引用、资质、效果或平台规则。没有依据的内容应删除、降格为观点，或放入发布前确认项。

## 必需方法框架

**REQUIRED SUB-SKILLS:** 读取并应用以下技能的判断标准：

- `dbs-content`
- `dbs-spread`
- `dbs-resonate`
- `dbs-xhs-title`
- `dbs-hook`
- `dbs-script-flow`
- `dbs-ai-check`
- `dbs-content-risk-check`

这些叶子技能中的“只诊断”“改稿前确认”和独立报告格式，不控制本技能。用户调用 `dbs-publish` 已明确授权完成整体改写；只复用它们的方法与边界，由本技能统一交付成稿。

## 接收材料

1. 读取用户粘贴的文本或附件内容，不修改原文件。
2. 提取目标平台、体裁、受众、目的、语气和长度要求。
3. 未指定平台时，默认输出通用中文自媒体文章。
4. 明确要求短视频、口播或逐字稿时，输出短视频逐字稿，并单独交付与内容直接相关的话题。
5. 只有输出体裁或发布形态无法从上下文判断且会明显改变结果时，最多追问一个问题。

### 小红书长文发布形态

用户要求发布“小红书长文”时，先确认图片承担什么功能。只要发布形态没有被明确说明，就停止成稿流程，最多追问一个问题并等待回答：

> 你准备让小红书把长文直接转成图片，还是使用自己的配图、把长文保留在笔记正文里？

最终回复只输出这个问题，不解释内部规则，不预告处理步骤，也不先给半成品。

“图片稍后处理”“图片到小红书再处理”“直接做”“不要问问题”都没有说明图片是否承载完整长文。遇到这些表达时仍然执行上面的确认，不得默认选择自有配图，也不得默认选择长文转图片。得到回答前不生成标题、正文或话题。

只有以下信息可以直接判定：用户明确说“小红书把长文转成图片”“文章生成多张图”，或明确说“使用自己的配图，图片不放长文”。已经明确时不要重复追问。

按答案选择一种输出形态：

| 发布形态 | 图片与文字的关系 | 输出组成 |
|---|---|---|
| 长文转图片 | 小红书把图片内标题和图片内长文转换成多张图片 | 图片内标题、图片内长文、笔记标题、正文小结、话题 |
| 自有配图 | 图片不承载完整长文，长文仍发布在笔记正文 | 单标题长文：标题、完整正文和话题 |

同一份原材料需要两种发布形态时，先完成并锁定一篇完整母稿，再做平台包装。没有明确要求精简时，两种形态复用这篇母稿，图片内长文和自有配图正文必须逐字一致；包装阶段只改变标题、正文小结和字段位置。复制格式检查可以统一换行符并删除空白行，但不得借此删改、压缩或重新生成母稿内容。

用户明确要求两个不同版本或不同篇幅时，分别建立母稿，并按各自要求包装；不要把这种情况与同一母稿的两种发布形态混在一起。

长文转图片模式同时遵守：

- 图片内标题负责图片首屏表达；笔记标题负责信息流点击。两者围绕同一主张，使用不同表达，不机械重复。
- 正文小结用于补充图片内容和承接互动，不把图片内长文重新压缩复述一遍。
- 为小红书长文编辑器提供可复制文本时，每段只按一次回车，不额外插入空白行。小红书 UI 本身会显示较大的段落间距；额外空行会让粘贴结果看起来像隔了两行。

自有配图模式不额外生成第二标题和正文小结。用户明确要求两种方案时，再分别输出两套。

### 小红书复制即发布格式

小红书成稿的每个字段单独放入一个 `text` 代码块。字段名放在代码块外，代码块内只放可复制内容。

每个复制块同时满足：

- 首尾没有空行；每段只按一次回车，不额外插入空白行，相邻段落之间恰好一次换行，不得出现连续空行；
- 不得包含 Markdown 标题符号、加粗、列表或分隔线；
- 不混入“标题”“正文”“话题”“备选方案”等字段说明；
- 不使用行末双空格制造换行；
- 话题单独成块，不混入正文末尾；
- 用户没有要求备选方案时，只交付最终选定版本。

交付前逐个检查复制块。验收标准是每个字段只需复制一次，粘贴后不删字、不补字、不合并空行即可进入小红书下一步。

在内部建立“来源账本”：

- 可以直接使用的事实与数字；
- 作者亲历、观点和明确偏好；
- 用户明确说明为真实的产品属性、课程内容、周期、价格和交易路径；
- 用户“想写”“准备宣传”或希望使用、但没有证据支持的营销话术；
- 把受众问题与产品连接起来的因果句、环境、机制、陪伴方式和服务能力；这些即使写成编辑性过渡，也属于产品属性，必须有来源；
- 引用或转述及其来源状态；
- 无法证明、不得写成事实的内容；
- 必须保留的措辞或边界。

来源账本默认不展示，但后续每个新增句子都必须能追溯到原文事实、合理的结构性转述或明确标注的观点。出现在原稿中的营销愿望不自动成为事实；不得把一个无法证明的承诺拆开后，重新包装成课程周期、服务内容或较弱的新承诺。

## 固定成稿流程

严格按以下顺序处理。每一步更新同一份内部工作稿，不分别输出诊断报告。

### 1．确定内容方向

应用 `dbs-content`：识别话题、体裁、受众、发布目的和一句话核心主张。材料包含多个方向时，只保留最能被原文支持、也最值得发布的一个方向。

### 2．确定传播立场

应用 `dbs-spread`：判断受众正在经历的具体处境、未被说出的情绪、内容站在哪一边，以及读者阅读或转发的真实动机。只保留能被原文支撑的情绪，不替作者制造焦虑。

### 3．收敛共鸣核心

应用 `dbs-resonate`：列出内部主张，选出唯一核心机制。删除无关主张，把必要的次要内容压缩成案例、解释或过渡。全文立场不得在代言者、建议者和教育者之间漂移。

### 4．生成并选择标题

应用 `dbs-xhs-title`：生成候选并选择一个最终标题。

- 小红书：标题必须能追溯到合适的公式，控制在 20 字以内，不得承诺正文无法兑现的结果。长文转图片模式分别选择图片内标题和笔记标题；两者功能互补。自有配图模式只选择一个最终标题。
- 其他平台：借用适合的心理触发机制，但不强行套用小红书字数、语气或公式。
- 标题不得引入原文没有的数据、权威或结果。

### 5．重做开头

应用 `dbs-hook`：让开头无需依赖标题也能成立，并与正文承诺一致。

- 短视频：前 5 秒建立话题、观看理由和有依据的可信度，确保能自然口播。
- 文章：前 1—3 段建立冲突、场景或问题，不急于把全文答案说完。
- 原文没有成绩、数据或权威时，不得为增强 Hook 而补造。

### 6．完成全文并检查流动

先写出完整工作稿，再应用 `dbs-script-flow` 检查段落顺序、逻辑跳跃、信息密度和语言流畅度。

- 短视频：长句拆分，术语立即解释，保证口播节奏。
- 文章：检查段落承接、重复论证和书面翻译腔，不强行改成口语碎句。
- 保留作者观点和真实语气；只改“怎么说”，不擅自改变“发生了什么”。

### 7．清理 AI 写作特征

应用 `dbs-ai-check` 扫描完成稿，并直接修复强、中信号。保留必要的毛边、个人判断和节奏变化；避免匀速排比、虚构读者、连续“不是 X 而是 Y”、假故事、万能金句和无依据的深刻化。

用户已授权整体成稿，因此不逐项追问。只有改动取决于作者真实经历或个人偏好且无法从原文判断时，保留原意并列入确认项，不代替作者回答。

### 8．执行发布风险门禁

应用 `dbs-content-risk-check` 检查标题、正文、行动邀请、利益关系、外链、联系方式、效果承诺、隐私、侵权和受限主题。

- 只做最小必要修改，保留强观点和个人风格。
- 无法证明的“第一”“唯一”“保证”“必然收益”等表述应删除或改成可验证事实。
- 销售内容只能使用用户明确确认的价格、课程内容、周期、名额、服务方式、退款条件和结果数据；缺少的产品属性应省略，不得代写。
- 不得用“用户缺少 X，所以我做了这个产品”等因果过渡，暗示产品提供未经确认的环境、机制、陪伴或效果；若产品如何解决问题没有来源，只能并列陈述已证实的产品事实与历史结果。
- 站外联系方式优先改为用户已说明可用的平台官方入口。
- 只有结论依赖当前平台政策时才查询官方规则。
- 不承诺“能发”“一定过审”或“百分百合规”。
- 无法在不改变事实或交易条件的情况下消除风险时，输出保守成稿，并把阻塞项放在正文之外。

## 条件增强

只在观察条件成立时启用，不进入默认流水线：

| 条件 | 使用 |
|---|---|
| 核心建立在未定义且会改变结论的抽象概念上 | `dbs-deconstruct` |
| 原材料无法形成可回答的问题或单一主张 | `dbs-good-question` |
| 用户明确要求历史同构、经典案例或证据研究 | `dbs-standard-answer` |
| 用户明确要求研究同行、账号或竞争参照 | `dbs-benchmark` |
| 成稿完成后，用户明确要求公众号 HTML 或微信排版 | `dbs-wechat-html` |

`dbs-content-system` 不属于单篇成稿流程，永不自动启用。

## 最终质量门禁

交付前逐项确认：

- 每个事实、数字、经历和引用均可追溯到来源账本；
- 全文只有一个核心主张，标题、开头和结尾一致；
- 标题承诺已在正文兑现；
- 没有明显重复、逻辑断裂或统一 AI 腔；
- 风险修改没有改变用户真实业务条件；
- 没有从被删除的营销承诺中衍生出新的课程周期、服务内容或效果暗示；
- 没有通过“所以”“因此”“正因为”等因果连接，把受众问题转化成未经确认的产品能力；
- 没有把内部分析、评分表或八份报告混入正文。
- 同一母稿输出两种小红书发布形态时，图片内长文与自有配图正文逐字一致；没有因包装方式改变而缩短或重写正文。
- 小红书成稿已经通过复制即发布格式检查，所有复制块都不含连续空行和多余格式字符。
- 短视频成稿完整交付标题、逐字稿和话题；话题没有混入逐字稿复制块。

任一项未通过，先修订工作稿，再重新检查相关项。

## 输出契约

通用文章和其他不需要双层文字载体的内容（短视频逐字稿除外），默认只输出：

```markdown
# 可直接发布版本

标题：{最终标题}

{完整正文或完整短视频逐字稿}

## 备选标题

1. {标题一}
2. {标题二}
3. {标题三}
```

短视频逐字稿模式按以下顺序输出，每个字段单独放入一个 `text` 代码块。逐字稿复制块内每段只按一次回车，相邻段落之间恰好一次换行，不得出现空白行；话题不混入逐字稿。用户没有要求备选标题时，不另附备选标题：

标题

```text
{最终标题}
```

逐字稿

```text
{第一段口播}
{第二段口播}
{后续完整逐字稿}
```

话题

```text
{与内容直接相关的话题}
```

小红书自有配图模式按以下顺序输出，正文复制块中不留空白行：

标题

```text
{最终标题}
```

正文

```text
{第一段}
{第二段}
{后续完整正文}
```

话题

```text
{与内容直接相关的话题}
```

小红书长文转图片模式输出：

图片内标题

```text
{供小红书转图使用的标题}
```

图片内长文

```text
{第一段}
{第二段}
{段落间只有一次换行的后续完整长文}
```

笔记标题

```text
{信息流中显示的第二个标题}
```

正文小结

```text
{补充图片内容并承接互动的简短正文；段落间只有一次换行}
```

话题

```text
{与内容直接相关的话题}
```

只有仍存在无法自动解决的问题时，再追加：

```markdown
## 发布前需要确认

- {具体事实、授权、资质或发布路径及其影响}
```

不要默认展示处理步骤、诊断分数、公式编号、修改说明或方法论。用户明确要求“说明为什么这样改”时，再提供简短编辑说明。

## 常见错误

- 依次输出八份报告，最后没有成稿：统一维护一份工作稿，只交付最终版本。
- 为了标题或 Hook 编造数字、权威和经历：所有增强都受来源账本约束。
- 所有平台都套小红书标题：只在目标为小红书时执行其硬性规则。
- 为了去 AI 味改掉作者立场：清理表达特征，不重写作者身份。
- 用免责声明保留虚假承诺：先删除或改正实质问题。
- 把“保证 7 天出结果”改成“7 天训练周期”，但用户没有确认周期：这是换一种方式编造，必须省略。
- 默认调用对标、内容系统或公众号 HTML：严格遵守条件增强表。

## 示例

用户提交一段“频繁更换 AI 工具导致产出下降”的经历，并要求整理成文章。应锁定“工具兴奋感会伪装成进步”为唯一核心，只使用用户给出的时间和产量数据，完成标题、开头、正文、AI 特征与风险检查，最后输出一篇成稿和三个备选标题，不展示八份中间报告。

## 语言

- 用户使用中文时，用自然、具体的中文成稿。
- 遵循《中文文案排版指北》。
